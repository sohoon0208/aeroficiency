# Demo script — target 2:48

Record from the frozen release in one clean browser session. Use an English voiceover, burned-in or YouTube captions, no music, no notifications, and a cursor size that remains visible after compression. Never show private tabs, account details, file paths, eligibility records, or tool credentials.

## Before recording

1. Reset Aerociency and verify `Baseline r1`, no analysis, and the preliminary-model disclaimer.
2. Verify the frozen release reports solver `aerociency-0.2.0` and reconfirm the documented baseline/candidate fixture.
3. Open the supported WebMCP agent environment and confirm all eight tool names.
4. Set browser zoom and recording resolution so 11–12 px operational text is readable at normal YouTube playback.
5. Close unrelated applications and disable notifications.
6. Keep the final candidate recipe available only as rehearsal guidance, not pasted into a tool response.

## Shot and narration plan

### 0:00–0:15 — Problem

**Screen:** Full Aerociency workspace, slow sweep across controls, 3D wing, and unavailable results.

**Voice:** “Preliminary wing design spans parameters, a 3D model, loads, structure, revisions, and warnings. A browser agent should not guess engineering state from pixels.”

### 0:15–0:34 — Shared model and WebMCP

**Screen:** Baseline protection, Site Tools badge, constraints, and normal Run button; briefly reveal the eight registered tools.

**Voice:** “Aerociency gives the human a complete manual workspace and exposes eight structured Site Tools over that same live model. Every tool uses explicit revisions, bounded SI inputs, and the same domain commands as the UI.”

### 0:34–0:52 — Baseline

**Screen:** Ask the canonical task. Agent calls `get_design_state`, then `run_aeroelastic_analysis` for baseline standard fidelity. Show progress and current result.

**Voice:** “The agent first reads revision one and runs the protected baseline. The dedicated worker trims to the shared target lift and converges the low-order aero-structural model.”

### 0:52–1:28 — Candidate creation and analysis

**Screen:** Agent creates Candidate A, updates skin to 1.65 mm and both webs to 2.00 mm, then runs standard analysis. Keep the fields, activity, and progress visible.

**Voice:** “It branches a candidate—never editing the baseline—then applies three bounded gauge changes. The page selects the candidate, advances its revision, marks old work stale, and records agent provenance before running the same solver.”

### 1:28–1:57 — Compare and inspect

**Screen:** `compare_designs`, five comparison deltas, five candidate constraint states, spanwise plot, and one critical station.

**Voice (use only after the frozen-release fixture is reconfirmed):** “The committed result is immutable and fingerprinted. This fixture reduces modeled structural mass by about 8.49 percent, with matched target lift, essentially unchanged wake-induced drag, and all configured checks passing. These are preliminary modeled tradeoffs—not flight-safety claims.”

### 1:57–2:24 — Human steer and conflict safety

**Screen:** Human changes span from 12.0 to 11.9 m. Show stale state. Invoke an update using the preceding revision; show conflict, then reread state.

**Voice:** “Now the human steers the design. Results immediately become stale. An agent write based on the old revision is rejected instead of overwriting the human. The response supplies the new revision and a safe next step.”

### 2:24–2:39 — Transparent model

**Screen:** Cycle Geometry, Aero loads, and Structure; show warnings and activity.

**Voice:** “Geometry, loads, deformation, constraints, warnings, and the actor-tagged history all come from committed state. The solver discloses exactly what it models and what it omits.”

### 2:39–2:48 — Close

**Screen:** Return to full workspace and Aerociency wordmark.

**Voice:** “Aerociency turns an agent from a fragile UI operator into a revision-safe engineering collaborator—while the human stays in control.”

## Recording acceptance

- Final duration between 2:35 and 2:50 and strictly below 3:00.
- Public YouTube visibility, working audio, English captions, and 1080p or better.
- Tool calls and resulting page changes are real and visible.
- The recorded solver version is `aerociency-0.2.0` and the fixture values were reconfirmed on that frozen release.
- No cut implies a failed or stale result is current.
- Baseline remains unchanged.
- Logged-out playback works from the Devpost link.
